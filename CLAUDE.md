This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Environment is managed by pixi (`pyproject.toml` `[tool.pixi.*]`); the package is installed editable into it.

```bash
pixi run test                                          # full suite (pytest tests/ -q; the smoke script is named smoke_*.py so pytest never collects it)
pixi run -e test python -m pytest tests/test_rig.py -q  # one file
pixi run -e test python -m pytest tests/test_rig.py::test_rig_mixed_hw -q   # one test
pixi run smoke-img                                     # tests/smoke_image_formats.py: rgb format/quality comparison (pillow + scikit-image, imgtest env only)
```

No linter/formatter is configured. Without pixi: `pip install -e .[test]` (numpy, opencv-python, h5py).

## Architecture

A small library of per-scene HDF5 writers/readers. Three public classes (`h5scene/__init__.py`, whose docstring is the canonical layout + usage spec — keep it, `README.md`, and `docs/schema.md` in sync when changing the format):

- **`H5Base`** (`h5base.py`) — a *pure file handle*: open/create (`mode` optional: `"r"`/`"r+"` on open, `"w"` on create), context-manager lifecycle, generic `attr`/`set_attr` and `meta`/`set_meta` accessors, `write_section`. Holds no shape or data. Keys are validated against the **subclass's** `ATTR_KEYS` / `META_KEYS` registries (dict name → Python type, `isinstance`-checked on write — numpy scalars accepted for `bool`/`int`/`float`; unknown names raise). `META_KEYS` values are `MetaSpec(type, dtype=…, length="T")` for array keys: dtype and axis-0 length ("T" = the scene's T) are checked in the base layer — `src_frame_idxs` must be int64 length T, `src_frame_ids` a utf-8 STRING array length T, `timestamps` a float64 array length T (E8; int input upcast, non-numeric rejected), `tags` a `dict[str, str]`. `set_meta` validates BEFORE deleting the old value; `None` removes; both single- and multi-key forms return self. `H5Cam.create/open`, `H5CamRig.build/open` are the public entry points; a failed subclass constructor after create calls `_abort_create()` (handle closed, file removed).
- **`H5Cam`** (`h5cam.py`) — single-camera sequence, shape `(T, H, W)` in `attrs.THW`; `/img/{t}` one dataset per frame (the image section is optional; the writers are SPLIT BY INPUT KIND — `set_rgb` = uint8 RGB **arrays** only, `set_rgb_bytes` = image **bytes**, `set_rgb_paths` = file **paths**; `set_bgr` = BGR arrays, colour reversed then stored through `set_rgb`; `rgb(t)`/`bgr(t)` decode, `img_bytes(t)` (E4) returns the stored jpg bytes undecoded). All three rgb writers enforce frame count == T and (H, W) == scene. Per-frame / streaming write (E5): `allocate(sections=…)` pre-creates the datasets, `write_frame(t, rgb=…, depth_mm=…|depth_meters=…, …)` one frame at a time (O(one frame) memory), `finalize()` checks every t was written. String frame ids (E1): `set_src_frame_ids([str…])` (unique, length T) + `index_of(fid)` / `indices_of([…])` O(1) after first call; a file without ids gives `src_frame_ids is None`. `H5Cam.peek(path)` (E7) returns the listing fields (file_type / THW / sections / meta) WITHOUT the full open validation. Data lives in the file. `is_metric` defaults False. `set_meta` is the single base form with two call styles: `set_meta(name, value)` (single key; None removes) and `set_meta(dataset=…, scene=…, …)` (multi-key convenience; a kwarg None means "leave as-is") — it is NOT overridden by subclasses. Open validates rgb keys AND section shapes against THW.
- **`H5CamRig`** (`h5camrig.py`) — merges N `H5Cam` files; its `META_KEYS` is **derived** from `H5Cam.META_KEYS` (cam keys minus `seq`/`src_frame_idxs`/`src_frame_ids`/`timestamps` — the rig IS the merged time axis, so its frames have no per-source ids; the rig's `suffix` is the one H5Cam already has) into one `(T, N, Hmax, Wmax)` file containing **references only, zero data bytes**: `/img/{t}_{n}` are HDF5 ExternalLinks to each camera's `/img/{t}` (jpg bytes, never re-encoded; `rgb(t, n)` decodes at that camera's native size), and `/depth /mask /K /T /depth_conf` are HDF5 virtual datasets (VDS) — ONE mapping per camera (`lay[:, n, :hh, :ww] = VirtualSource(path, name, (T, hh, ww))`, pad region -> fillvalue) — mapping the cameras' compressed data. Build = validate first, write to a temp file, `os.replace` into place.

Helper package, shared by both subclasses (`h5scene/codecs/` — one code path per section):
- `codecs/sections.py` — the declarative `SECTIONS` table (`Spec`: dtype / compression / compression_opts / shuffle / fillvalue / frame2d); it drives the H5Cam writers, the rig VDS build, `has()`, and `test_compression_policy`. `has()` answers sections and the img section only (meta keys: `meta(name) is not None`). `is_metric()` reads `attrs.is_metric` (always written by create/build).
- `codecs/depth.py` — the `to_mm`/`to_meters_mm` converters (int = mm, float = meters) and the 0/65535 sentinel rules, the `(h, w)` aspect-ratio + `INTER_NEAREST` resize rules, the 0-1 `to_conf` guard (float-only), the derived `depth_mask`.
- `codecs/rgb.py` — jpg q≤95 encoding + DQT-table quality fingerprinting; the **colour-order boundary** (public API is RGB; cv2's BGR is converted at encode/decode); the rgb input normalizers are SPLIT BY KIND — `normalize_img_array` (uint8 arrays only) / `normalize_img_bytes` (image bytes; q≤95 cv2 jpgs kept verbatim, everything else re-encoded q95) / `normalize_img_paths` (file paths); `jpeg_hw()` reads a frame's size from the SOF header alone (the rig's size check avoids full decodes).
- `codecs/pose.py` — K `(3,3)` / T `(4,4)` broadcast + the convention checks (E3): `check_K` enforces the OpenCV PINHOLE form (fx, fy > 0, K[2,2]=1, zero skew / K[2,1] / K[2,0]); `check_pose` enforces camera-to-world (last row [0,0,0,1], orthonormal R, det 1) — `set_K` / `set_pose_c2w` run them on every row before writing.

### Format invariants worth knowing before editing

- **img** (the `rgb`/`bgr` accessors): stored in `/img/{t}` as jpg bytes with quality ≤ 95 in **RGB channel order** (a red image has a high R channel in the stored jpg and reads back red). Incoming jpg with detected cv2/libjpeg q > 95 or other encodings (PNG, …) is re-encoded to q95; detection only knows the cv2 fingerprint qualities `{1,20,50,70,90,95,99,100}` (a q80 cv2 jpg is "unknown" → re-encoded). Choice justified in `tests/probes/README.md`.
- **depth**: uint16 millimetres; **both 0 and 65535 are invalid** sentinels. Writer maps >= 65.535 m to 0 (never saturates); reader re-clips `>= 65535 -> 0` — 65535 is never a valid depth, so the max representable value cannot round-trip as valid. gzip4 + shuffle. May be stored at smaller `(h, w)` only if `h*W == w*H`; reads resize with `INTER_NEAREST` so sentinels are never interpolated. `depth_conf` (f16) must share depth's `(h, w)`. In the **rig**, depth must be stored at the camera's NATIVE (H, W) — downsampled depth is rejected (a VDS block cannot upscale).
- **mask** bool gzip4 no shuffle; **K / T** stored raw (gzip measured larger for short sequences). `tests/test_compression_policy.py` pins these filter choices.
**attrs vs /meta** (decision D1) and `attrs.file_type`: data-side properties (`THW`/`TNHW`, `is_metric`, rig `cam_files`/`cam_hw`) are file attrs, and every h5scene file also pins `attrs.file_type` (`"h5cam"` / `"h5camrig"` / `"h5geo"`) at create/build — the constructors reject a mismatched tag; dataset-side context goes in `/meta` (`dataset`, `scene`, `seq`, `suffix`, `split`, optional `src_frame_idxs` only when ≠ `arange(T)` — enforced, length must be T, `src_frame_ids` (E1, unique strings, length T) and `timestamps` (E8, float64, length T), `tags/*` values must be str).
- - **Rig rules** (checked at build, before any file is written; the output dir is created): same T, `is_metric`, and section set; rgb present in ALL cameras or in NONE; **`dataset` + `scene` must match** (the cameras' seqs merge into one time axis — the rig has **no `seq`** in its registry); exactly one of H/W may differ (the other becomes max, top-left aligned); depth at native (H, W); the output path is not one of the cameras (it would be overwritten); shared `split`/`tags` inherited only when every camera agrees. Source camera paths stored RELATIVE to the rig file's directory in `attrs.cam_files` (VDS/ExternalLinks resolve that way, so the rig survives a move/copy with its cameras) plus a check that each camera's attrs.THW still equals `(T, *cam_hw[n])` and that every mapped section is still present in the camera with the mapped shape; opening a rig raises `FileNotFoundError` (missing) or `ValueError` (THW changed, or a mapped section deleted/re-sized) — a VDS would otherwise silently read fillvalue zeros. No file size / mtime is involved: a metadata edit on a camera does not break the rig.

`docs/schema.md` (Chinese) documents the per-class file schema (attrs, sections, /meta keys) for H5Base / H5Cam / H5CamRig; keep it in sync when adding/removing keys.

### Tests

`tests/` uses pytest with `tmp_path` and synthetic data; `tests/probes/` holds real-scene crops (ADT frame) used as inputs. `tests/test_issue_bugs.py` pins the reviewed-bug fixes (per-t VDS reads, downsampled rejection, colour round-trip, failed-build preservation, frame-count check, meta no-erase, camera-THW verification, empty/duplicate paths).
